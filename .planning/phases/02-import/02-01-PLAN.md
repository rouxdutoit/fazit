# Plan 02-01: tracer, a mailbox usage export becomes a scan and a report

## Goal

A council IT officer can point `fazit import` at the mailbox usage export from the Microsoft 365 admin centre and get a `scan.json` and a report on their own machine, with no sign-in and no network, and with nothing kept but counts and sums. This plan proves that path end to end for one export, with honest reasons for everything the export does not carry and real refusals on the one path.

## Layout file shape

`src/fazit/rules/exports.yaml` starts with the SPDX line and a comment saying where header names come from. Its shape, with the mailbox usage layout this plan registers:

```yaml
unsupplied_reasons:
  exchange_recipients: needs_recipient_export
exports:
  - source: import.mailbox_usage
    collector: mailbox_usage
    kind: period
    reference_url: https://learn.microsoft.com/en-us/graph/api/reportroot-getmailboxusagedetail?view=graph-rest-1.0
    checked_on: "2026-11-22"
    documented: [Report Refresh Date, User Principal Name, Display Name, Is Deleted, Deleted Date, Created Date, Last Activity Date, Item Count, Storage Used (Byte), Issue Warning Quota (Byte), Prohibit Send Quota (Byte), Prohibit Send/Receive Quota (Byte), Deleted Item Count, Deleted Item Size (Byte), Deleted Item Quota (Byte), Has Archive, Report Period]
    columns:
      refresh_date: [Report Refresh Date]
      period: [Report Period]
      deleted: [Is Deleted]
      user: [User Principal Name]
      item_count: [Item Count]
      storage_bytes: [Storage Used (Byte)]
    required: [refresh_date, period, deleted, item_count, storage_bytes]
    identifiers: [user]
    findings:
      mail.mailbox_count: {measure: rows, coverage: complete}
      mail.storage_bytes: {measure: sum, column: storage_bytes, coverage: complete}
      mail.item_count: {measure: sum, column: item_count, coverage: complete}
```

Meaning: `columns` maps a role to the header names accepted for it (the first is the canonical name used in messages; plan 02-06 adds observed variants). `required` roles must all be present for a header to match. `identifiers` roles are read only to detect concealment (plan 02-02, D-127). `documented` is the full header from the cited page, used by tests to build fixtures and by the registry check. `findings` says how each finding is measured from rows that are not deleted (`rows`: their number; `sum`: the sum of a whole-number column) and with which coverage (D-125). `unsupplied_reasons` gives the reason for a collector's findings when its export was not supplied.
