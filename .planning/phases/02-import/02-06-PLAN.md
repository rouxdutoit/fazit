# Plan 02-06: the usage layouts accept what the admin centre really writes, in English and German

## Goal

The usage layouts were built from Microsoft's documented Graph headers. The founder has now seen what the admin centre's Export button actually writes, once in English and once in German. This plan makes the five usage layouts accept exactly that, so an officer's real files import whichever language the admin centre is set to.

<objective>
Built on the report redesign merged into main (D-91), on plans 02-01 to 02-05 (the five usage layouts exist after 02-05), and on the founder's observation in `.planning/phases/02-import/02-HEADERS.md` (plan 02-00). Task 1 checks all of them and stops if anything is missing.

Task 1 lets a layout cite an observation and applies it to the mailbox usage and active users layouts. Task 2 applies it to the OneDrive, SharePoint site and Teams layouts. Task 3 adds the German fixtures and equality tests and records the answers the observation gives.

Purpose: D-116 ("usage layouts start from Microsoft's documented Graph headers and are adjusted from the observation"). Split out of the snapshot plan so it can run as soon as the observation and plan 02-05 exist.
Output: an extension of the layout schema, observed names in `rules/exports.yaml`, German fixtures where needed, tests. `rules/exports.yaml` is not read by the report, so the demo reports do not change.

Run order of the phase: 02-00 and 02-01 (wave 1); 02-02 (wave 2); 02-03 and 02-04 (wave 3); 02-05 (wave 4); 02-06 and 02-07 (wave 5); then one plan per wave: 02-08, 02-09, 02-10, 02-11, 02-12, 02-13, 02-14 (waves 6 to 12). This plan shares no file with 02-07 to 02-10, so if the founder's observation arrives late it can run after any of them, as long as it runs before 02-11.
</objective>

- Tests: the registry test over observed headers and the German equality tests in `tests/test_import_layouts.py`.
