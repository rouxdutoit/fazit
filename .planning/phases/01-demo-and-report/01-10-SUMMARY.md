# Plan 01-10 summary

A complete licence inventory requires `coverage.scanned` and `coverage.total` to equal the number of product rows, with `coverage.failed` set to zero. Contradictory coverage exits 2 at `licences.coverage`. In-memory reports apply the same check. Both bundled inventories record the counts explicitly, and both site reports were regenerated.

Every listed SKU in the catalogue must include all its roster plan GUIDs, including plans with no workload and products with zero assignments. An omitted GUID makes every unconfirmed add-on and bundled signal unknown with `licence_plan_list_incomplete`. A classified assignment still establishes presence. The product table counts extra unclassified plans and gives the catalogue fix. When a known roster is incomplete and also contains an unclassified row, readiness shows the roster omission and the product table shows the unclassified row count.

## Consistency audit

- Licence products and coverage were checked on JSON load and on direct rendering. The product count is derived from the rows and the assignment signals are derived from classified plans. The scan loader discards unregistered finding IDs, including attempts to supply derived licence figures. Duplicate SKU identifiers already fail validation. Privacy-safe copies preserve row cardinality, including anonymous products and plans.
- Partial and unknown licence inventories already leave unconfirmed signals unknown, as does a partial licence collector. An empty inventory remains unknown even with a consistent count of zero. Purchased and assigned are seat counts. The service plan list records product components.
- Plan completeness is checked by GUID membership. Repeating another plan can keep the list the same length and still leaves the omitted GUID missing. The duplicate-row regression verifies every unconfirmed signal and the surviving assignments. A missing licence block produces no derived evidence.
- The other workload findings store scalar counts, sizes and confirmations. Their coverage describes the collection scope, and the scan has no per-item rows to reconcile. The collector and finding lists reject duplicate IDs. Omitted required findings and known skipped or partial collectors already prevent Ready. Permissions are listed as collection metadata.
- The Windows-only application totals and number of answered web-version questions are derived from the list in `inputs.yaml`. An unanswered entry leaves coverage partial. Mapping needs read a declared finding, and the readiness and suggested-path lists count evaluated workloads. These paths have no independent row counts to reconcile.

## Public interfaces

- `model.load_scan(path: Path, catalogue: Catalogue) -> Scan`, `load_scan_text(text: str, file_name: str, catalogue: Catalogue) -> Scan` and `scan_to_json(scan: Scan, *, plans: tuple[rules.ServicePlan, ...]) -> str` are the scan I/O. Schema major 1 is supported.
- Frozen `model.Scan(schema_version: str, tool: ToolInfo, generated_at: str, source_kind: str, collectors: tuple[Collector, ...], findings: tuple[Finding, ...], licences: Licences | None, dropped_count: int = 0)` exposes `finding(finding_id: str) -> Finding | None` and `collector(collector_id: str) -> Collector | None`. The frozen records are `ToolInfo(name: str, version: str)`, `Collector(id: str, status: str, reason: str | None, permissions_used: tuple[str, ...])` and `Coverage(kind: str, scanned: int | None = None, failed: int | None = None, total: int | None = None)`.
- Frozen `model.Finding(id: str, workload: str, value: FindingValue | None, unit: str | None, provenance: str, collector: str | None, source: str | None, collected_at: str | None, period: str | None, coverage: Coverage | None, missing_reason: str | None)` uses `FindingValue = int | bool`. Frozen `model.Licences(collector: str, source: str, collected_at: str, coverage: Coverage, products: tuple[Product, ...])` provides `check_complete_coverage(file_name: str) -> None`. It raises `InputError` with code `invalid_licence_coverage` for a complete claim that disagrees with the rows. Frozen `Product(sku_part_number: str | None, sku_guid: str | None, purchased: int, assigned: int, service_plans: tuple[model.ServicePlan, ...])` exposes `key: tuple[str, str] | None`. Frozen `model.ServicePlan(name: str | None, guid: str | None)` is an observed plan.
- `catalogue.load_catalogue(path: Path | None = None) -> Catalogue` returns the frozen catalogue. Its fields are `workloads: tuple[WorkloadEntry, ...]`, `findings: tuple[FindingEntry, ...]`, `collector_ids`, `source_codes`, `reason_codes`, `permissions`, `provided_sources` and `licence_sources` as `frozenset[str]`, `file_name: str`, `checksum: str | None` and `sku_exceptions: frozenset[tuple[str, str]]`. The frozen entries are `WorkloadEntry(id: str, label: str)` and `FindingEntry(id: str, workload: str, type: str, unit: str | None, label: str, provided: str, headline: bool, measured_by: frozenset[tuple[str, str]] = frozenset())`. The catalogue provides `workload_ids: tuple[str, ...]`, `finding(finding_id: str) -> FindingEntry | None` and `accepts_sku_part_number(part_number: object, guid: str) -> bool`.
- `rules.load_service_plans(catalogue: Catalogue, path: Path | None = None, *, checksums: MutableMapping[str, str] | None = None) -> tuple[ServicePlan, ...]` reads the roster. Frozen `rules.ServicePlan` records `sku_part_number`, `sku_guid`, `name`, `guid`, `signal` and `reference_url` as strings, `workload: str | None`, `checked_on: date` and `note: Mapping[str, str] | None`. `classify_product(product: model.Product, plans: tuple[ServicePlan, ...]) -> tuple[ServicePlan | None, ...]` gives matches in observed order. `licence_findings(scan: Scan, plans: tuple[ServicePlan, ...], catalogue: Catalogue) -> tuple[Finding, ...]` returns the product count followed by add-on and bundled signals in catalogue workload order.
- `rules.evaluate(findings: Mapping[str, Finding], rule_set: StatusRuleSet, catalogue: Catalogue, *, collectors: Mapping[str, Collector] | None = None, alternatives: Mapping[str, Finding] | None = None) -> tuple[WorkloadStatus, ...]` returns frozen `WorkloadStatus(workload: str, status: str, reason_code: str | None, missing: tuple[MissingEvidence, ...], deciding: StatusRule | None, notes: tuple[StatusRule, ...], evidence: tuple[Finding, ...])`, with `incomplete: bool`. Frozen `MissingEvidence(finding_id: str, reason_code: str, collector: str | None)` describes a gap.
- `inputs.load_inputs(path: Path, catalogue: Catalogue) -> Inputs` and `load_inputs_text(text: str, file_name: str, catalogue: Catalogue) -> Inputs` load manual answers. `report.render_report(scan: Scan, *, lang: str, profile: str = "opendesk", catalogue: Catalogue | None = None, inputs: Inputs | None = None) -> str` renders HTML. `render_demo(scan: Scan, *, lang: str, profile: str, catalogue: Catalogue, inputs: Inputs) -> tuple[str, str]` returns HTML and the scan copy. `report_file_name(generated_at: str, *, lang: str) -> str` returns the dated filename. `output.write_inside(out_dir: Path, file_name: str, text: str) -> Path` and `write_files(out_dir: Path, outputs: Mapping[str, str]) -> tuple[Path, ...]` return resolved output paths.
- The Typer app is `befund.cli.app` and the entry point is `befund.cli:main() -> None`. `befund [--debug] demo [--lang en|de] [--sample town|nonprofit] [--profile opendesk|nextcloud|generic] [--out DIR]` defaults to `en`, `town`, `opendesk` and `./report`. `befund [--debug] report SCAN_JSON [--inputs FILE] [--lang en|de] [--profile opendesk|nextcloud|generic] [--out DIR]` resolves language and profile from flags, inputs and defaults. Both commands support `--help` and print the absolute `report-<YYYY-MM-DD>-<lang>.html` path last. Demo also writes `scan-<YYYY-MM-DD>-<lang>.json` and `inputs-<YYYY-MM-DD>-<lang>.yaml`. Global `--version` prints the installed version. A bad input prints one localized sentence and exits 2. `--debug` exposes the exception.
