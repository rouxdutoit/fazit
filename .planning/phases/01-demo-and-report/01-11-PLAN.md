# Plan 01-11: detectable contradictions, and the trust boundary stated

Source: `01-CONFIRM-3.md` (third gate on HEAD `4e532e4`). Read it first; it gives a reproduction for each item. Write `01-11-SUMMARY.md` mapping each item to the change and its CLI regression test.

## The boundary (orchestrator decision, record as DECISIONS.md D26)

A scan file is input from whoever produced it. Befund rejects every contradiction it can detect cheaply inside the scan and inputs, and labels where every figure came from. It cannot detect a fabricated scan that is internally consistent: such a file produces a fabricated report, as any assessment built on false data would. The report's appendix already names the producing tool, its version and the scan's origin; `SECURITY.md` and both READMEs must now state this boundary in two plain sentences, and say that a report is only as trustworthy as the tool and person that produced its scan.

## Fixes (each with a CLI regression test reproducing the gate's case)

1. **Sample evidence cannot pass as live.** A finding whose source code starts with `sample.` forces the simulation notice, whatever `source_kind` says; `source_kind` `live` or `import` with any `sample.` source is an input error.
2. **Collector status and reason agree.** A collector with status `ok` must have no reason; `partial` and `skipped` must have one. Anything else is an input error.
3. **Dates are possible.** For every finding, the period end must not be after `collected_at`, and `collected_at` must not be after `generated_at`; otherwise input error.
4. **Licence identity.** When a product's SKU part number or SKU GUID is in the catalogue, the other must match the catalogue's pair, or input error. An assigned product (assigned > 0) with a missing identifier or an empty plan list is unclassified: absence of add-ons is unknown everywhere, as in plan 01-09. Products with zero assigned seats do not affect signals.
5. **Totals that contradict each other.** If the directory reports licensed accounts greater than zero but the licence inventory assigns zero seats in total, absence of add-ons is unknown everywhere, with the reason "licence assignments contradict licensed accounts". A finding whose coverage total contradicts a related count in the same scan, where the catalogue declares the relation (add a `coverage_total_from` field to `rules/findings.yaml`, for example `teams.teams_with_guests_count` takes its total from `teams.team_count`), is an input error.
6. **A measured positive is always a lower bound.** Whatever its coverage kind (`complete`, `partial` or `unknown`), a measured value above zero establishes that at least that many exist; a smaller supplied answer is a conflict (no Ready), as in plan 01-08 item 5.
7. **Two answers that disagree are a conflict.** When a provided finding in the scan and an answer in `inputs.yaml` disagree, both are shown, the workload cannot be Ready, and neither silently wins, whatever their dates.
8. **The inputs source belongs to the inputs file.** A finding in `scan.json` with provenance `provided` and source `inputs_yaml` is an input error; that source code is reserved for answers loaded from `inputs.yaml`.
9. **Mapping needs use the same evaluation as readiness.** "Needed by this organisation" reads the evaluated evidence: if the readiness evaluation treats the deciding finding as incomplete, skipped or in conflict, the mapping shows Unknown, never a measured No.
10. **Wrong organisation (low-cost mitigation).** The report header names both input files with their dates (`generated_at` of the scan, `as_of` of the inputs) next to each other, so a mismatch is visible. Do not add matching logic.
