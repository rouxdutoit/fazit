## Public interfaces

- `rules.STATUSES = ("ready", "needs_work", "blocker", "unknown")`. `rules_dir() -> Traversable` returns the packaged rules directory.
- `load_service_plans(catalogue: Catalogue, path: Path | None = None, *, checksums: MutableMapping[str, str] | None = None) -> tuple[ServicePlan, ...]`
- `load_status_rules(catalogue: Catalogue, path: Path | None = None, *, checksums: MutableMapping[str, str] | None = None) -> StatusRuleSet`
- `load_risky_file_types(catalogue: Catalogue, path: Path | None = None, *, checksums: MutableMapping[str, str] | None = None) -> tuple[RiskyKind, ...]`
- `classify_product(product: model.Product, plans: tuple[ServicePlan, ...]) -> tuple[ServicePlan | None, ...]` returns one match per observed plan in product order. `licence_findings(scan: Scan, plans: tuple[ServicePlan, ...], catalogue: Catalogue) -> tuple[Finding, ...]` returns the product count followed by the add-on and bundled signals for each workload in catalogue order. It returns an empty tuple without a licence block.
- `evaluate(findings: Mapping[str, Finding], rule_set: StatusRuleSet, catalogue: Catalogue, *, collectors: Mapping[str, Collector] | None = None) -> tuple[WorkloadStatus, ...]` returns one status per catalogue workload in catalogue order. Pass the scan collectors by ID to check collector state.
- `select_evidence(recorded: Finding | None, supplied: Finding) -> Finding` selects the value for evaluation. `evidence_conflicts(measured: Finding, provided: Finding) -> bool` flags a partial positive measurement against a supplied zero.
- The frozen rule dataclasses are `ServicePlan(sku_part_number: str, sku_guid: str, name: str, guid: str, workload: str, signal: str, reference_url: str, checked_on: date, note: Mapping[str, str] | None)`, `Condition(finding: str, op: str, value: FindingValue | None, provenance: str | None = None)`, `StatusRule(id: str, when: tuple[Condition, ...], status: str, reason: Mapping[str, str])`, `WorkloadRules(ready: tuple[Condition, ...], ready_reason: Mapping[str, str], rules: tuple[StatusRule, ...])` and `StatusRuleSet(workloads: Mapping[str, WorkloadRules], file_name: str)`.
- `MissingEvidence(finding_id: str, reason_code: str, collector: str | None)`, `WorkloadStatus(workload: str, status: str, reason_code: str | None, missing: tuple[MissingEvidence, ...], deciding: StatusRule | None, notes: tuple[StatusRule, ...], evidence: tuple[Finding, ...])` and `RiskyKind(id: str, finding_id: str, label: Mapping[str, str], note: Mapping[str, str], extensions: tuple[str, ...])` are frozen. `WorkloadStatus.incomplete: bool` reflects whether `missing` is populated. `deciding` holds the winning problem rule, and `notes` holds the other fired rules in file order.
- `catalogue.load_catalogue(path: Path | None = None) -> Catalogue` also records `Catalogue.file_name: str = "findings.yaml"` and `Catalogue.checksum: str | None = None`. The finding catalogue adds the boolean answer `telephony.in_use` and the reason codes `licence_not_classified` and `coverage_unknown`.
- `report.render_report(scan: Scan, *, lang: str, catalogue: Catalogue | None = None, provided: tuple[Finding, ...] = ()) -> str`, `report_file_name(generated_at: str, *, lang: str) -> str` and `SECTION_ORDER` are the report interfaces. Pass provided findings separately so the renderer can show both observations and apply the evidence precedence. The template now renders `header`, `found`, `readiness`, `attention`, `appendix` and `footer` in that order.
- `cli.app` and `cli.main() -> None` expose `m365-exit-scan [--debug] demo [--lang en|de] [--sample town|nonprofit] [--out DIR]` and `m365-exit-scan [--debug] report SCAN_JSON [--lang en|de] [--out DIR]`. Defaults are `en`, `town` and `./report`. Global `--version` prints the version. Both commands print the absolute HTML path on the last line. Input errors exit 2 with one localized sentence unless `--debug` is set.
