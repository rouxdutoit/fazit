# Plan 01-04 summary

`demo` and `report` render nineteen functions for each of the openDesk, Nextcloud and generic profiles. The mapping table shows coverage, the documentation check date, up to three evidence summaries, and the status and reason from the associated workload. The appendix records the full mapping and the checksum of the bytes read. The attention section separates the documented transfer gap from whether the organisation needs the function. The suggested path lists blockers, unknowns with their fixes, and workloads where the evidence shows no obstacle.

## Public interfaces

- `rules.PROFILES = ("opendesk", "nextcloud", "generic")`. `rules.COVERAGE_LADDER` is ordered as `in_suite`, `in_suite_with_limits`, `announced`, `component_vendor_solution`, `open_source_community`, `open_source_third_party`, `proprietary_third_party`, `not_available`.
- `rules.FunctionMapping(function: str, workload: str, microsoft: Mapping[str, str], replacement: Mapping[str, str], coverage: str, reference_url: str | None, checked_on: date | None, note: Mapping[str, str] | None, need_finding: str | None = None)` is frozen. The bilingual fields are read-only mappings. `need_finding`, when set, names a catalogue boolean in the same workload.
- `rules.Mapping(profile: str, label: Mapping[str, str], description: Mapping[str, str], product_profile: bool, no_function: tuple[str, ...], functions: tuple[FunctionMapping, ...], file_name: str)` is frozen. Here the field type `Mapping[str, str]` means `collections.abc.Mapping`.
- `rules.load_mapping(profile: str, catalogue: Catalogue, directory: Path | None = None, *, checksums: MutableMapping[str, str] | None = None) -> Mapping` reads `mappings/<profile>.yaml` from the packaged rules directory or from the supplied rules directory. On success the optional checksum mapping receives the SHA-256 digest under the YAML basename. `rules.mapping_need(finding: Finding | None) -> str` reports `yes`, `no` or `unknown` from the selected evidence.
- `report.render_report(scan: Scan, *, lang: str, profile: str = "opendesk", catalogue: Catalogue | None = None, provided: tuple[Finding, ...] = ()) -> str`. The template renders `header`, `found`, `readiness`, `moves`, `attention`, `path`, `appendix` and `footer` in that order. `SECTION_ORDER` also reserves the `costs` position. The new HTML attributes include `data-function`, `data-mapping-details`, `data-subsection="cannot-be-moved"`, `data-gap`, `data-need`, `data-path-status` and `data-path-workload`.
- `cli.app` and `cli.main() -> None` expose `fazit [--debug] demo [--lang en|de] [--sample town|nonprofit] [--profile opendesk|nextcloud|generic] [--out DIR]` and `fazit [--debug] report SCAN_JSON [--lang en|de] [--profile opendesk|nextcloud|generic] [--out DIR]`. Defaults are `en`, `town`, `opendesk` and `./report` where applicable. Global `--version` prints the version. Both commands print the absolute HTML path last. An invalid profile produces one localized error sentence and exits 2.

## Coverage decisions

- openDesk uses `in_suite_with_limits` for `team_files` because site and library rules need a separate review, `office_editing` because complex document fidelity remains unverified, `security_and_compliance` because organisation-wide retention and legal holds remain unverified, `forms_tasks_bookings` because project and personal tasks are documented while general forms and public bookings remain unverified, and `application_integrations` because each existing connection needs checking.
- openDesk uses `not_available` for `sharepoint_workflows`, `teams_chat_history` and `vba_macros` because the project docs do not establish direct transfer. The documented scope also leaves `device_management`, `desktop_operating_system`, `windows_applications` and `automation_and_low_code` outside the suite. The handoff's desktop example was replaced with a separately managed workstation operating system. `telephony` is `not_available` because the documented Jitsi SIP dial-in covers meetings and leaves office extensions and call routing unverified.
- Nextcloud uses `in_suite_with_limits` for nine functions. `identity_management` covers its own accounts, `mail_and_calendar` needs a separate mail server, and `team_files` leaves site and library rules to review. `office_editing` needs an editing service and document tests. `automation_and_low_code` leaves existing apps and connectors to review or rebuild. `telephony` requires a SIP gateway and leaves call routing and queues to check. The documented retention rules for `security_and_compliance` cover tagged files. `forms_tasks_bookings` requires review of existing configurations, and `application_integrations` requires checking each connection.
- Nextcloud uses `not_available` for `sharepoint_workflows`, `teams_chat_history` and `vba_macros` because the docs show options for new workflows, moving to Talk and supported editor macros, while direct transfer remains unverified. The core component scope puts `device_management`, `desktop_operating_system` and `windows_applications` outside the suite. `single_sign_on` uses the documented community OIDC Identity Provider app.
