# Plan 01-05 summary

`befund report --inputs` reads manual answers, counts, software and cost inputs. The report shows the organisation name, dates and provenance, uses the selected evidence for readiness, and displays alternative observations alongside it. `demo` uses the bundled inputs and writes an exact copy through the shared output writer. The bilingual `inputs.example.yaml` and both interview checklists cover the inputs accepted by the loader.

## Public interfaces

- `inputs.CurrentCosts(microsoft_licences_per_year: Decimal | None = None, other_it_per_year: Decimal | None = None)` is frozen.
- `inputs.ScenarioInputs` is frozen. `users`, `training_staff` and `parallel_running_months` are `int | None`. `retained_microsoft_licences_per_year`, `hosting_per_user_per_month`, `operations_per_year`, `other_recurring_per_year`, `one_time_migration`, `application_adaptation`, `external_advice`, `training_days_per_person`, `training_day_rate` and `productivity_loss` are `Decimal | None`. All fields default to `None`. Whole training days are also stored as `Decimal`.
- `inputs.WindowsSoftware(name: str, users: int | None = None, vendor_has_web_version: bool | None = None)` is frozen.
- `inputs.Inputs` is frozen. `organisation_name`, `currency`, `language`, `target_profile` and `as_of` are `str | None`, defaulting to `None`. `as_of` is an ISO date. `amounts_are_invented: bool` defaults to `False`. `current_costs: CurrentCosts`, `partial_exit: ScenarioInputs` and `full_exit: ScenarioInputs` default to instances with empty fields. `windows_only_software: tuple[WindowsSoftware, ...] | None` defaults to `None`. An empty tuple confirms that there are no such applications. `provided_counts: Mapping[str, int | None]` and `confirmations: Mapping[str, bool | None]` default to empty read-only mappings and preserve explicit null answers.
- `inputs.empty_inputs() -> Inputs`, `inputs.load_inputs_text(text: str, file_name: str, catalogue: Catalogue) -> Inputs` and `inputs.load_inputs(path: Path, catalogue: Catalogue) -> Inputs` construct the model. The YAML keeps both scenarios under `target_costs`.
- `inputs.provided_findings(inputs: Inputs, catalogue: Catalogue) -> tuple[Finding, ...]` derives answers in catalogue order. It assigns source `inputs_yaml`, the input date as `collected_at`, and no collector. A known software count can be a lower bound with partial answer coverage.
- `inputs.combine(scan: Scan, provided: tuple[Finding, ...]) -> tuple[Scan, tuple[Finding, ...]]` returns a scan for report evaluation and the measured or provided alternatives for display. Both observations retain their values and metadata. `demo` serializes the original validated scan.
- `parsing.parse_yaml(text: str, file_name: str, *, quoted_fields: tuple[str, ...] = ()) -> object` can require quoted strings at specified dotted YAML paths.
- `report.render_report(scan: Scan, *, lang: str, profile: str = "opendesk", catalogue: Catalogue | None = None, provided: tuple[Finding, ...] = (), inputs: Inputs | None = None, sample_inputs: bool = False) -> str`. Parsed answers take precedence over the legacy `provided` argument for the same ID before evidence selection. `sample_inputs=True` labels the bundled interview answers. The software table uses `data-software-entry` on each application row.
- `cli.app` and `cli.main() -> None` expose `befund [--debug] report SCAN_JSON [--inputs FILE] [--lang en|de] [--profile opendesk|nextcloud|generic] [--out DIR]`. Report language and profile resolve from flags, the inputs file, then `en` and `opendesk`. Messages follow `--lang` and otherwise use English. `befund [--debug] demo [--lang en|de] [--sample town|nonprofit] [--profile opendesk|nextcloud|generic] [--out DIR]` uses its flags and defaults of `en`, `town` and `opendesk`. `--out` defaults to `./report`. Global `--version` prints the version. Both commands print the absolute `report-<YYYY-MM-DD>-<lang>.html` path last. Demo also writes `scan-<YYYY-MM-DD>-<lang>.json` and `inputs-<YYYY-MM-DD>-<lang>.yaml`. Bad inputs exit 2 with one localized error sentence unless `--debug` is set.

- D-66 replaces the older town mail expectation with Needs work and incomplete evidence, yielding the rendered town counts above.
- D-67 and D-77 supersede blanket measured precedence. Complete measurements decide, complete manual evidence can replace a partial measurement, and a confirmed positive lower bound survives a conflicting supplied zero. One confirmed application without a web version plus one unanswered shows Blocker with incomplete evidence under D-66.
- D-68 adds `telephony.in_use` to the samples and example and to both checklists. The nonprofit explicitly confirms non-use. The town confirms use and that a replacement is unavailable.

The renderer preserves the earlier `provided` argument and labels answers loaded by `demo` as sample interviews independently of the scan and the price flag. A rebuild with `--inputs` identifies those answers by their input-file source.
