## Public interfaces

- `catalogue.load_catalogue(path: Path | None = None) -> Catalogue`. Frozen `FindingEntry(id: str, workload: str, type: str, unit: str | None, label: str, provided: str, headline: bool, measured_by: frozenset[tuple[str, str]] = frozenset())` stores allowed collector and source pairs. Frozen `Catalogue` holds `workloads: tuple[WorkloadEntry, ...]`, `findings: tuple[FindingEntry, ...]`, `collector_ids`, `source_codes`, `reason_codes`, `permissions` and `provided_sources` as frozensets of strings, `sku_exceptions: frozenset[tuple[str, str]]`, `file_name: str` and `checksum: str | None`. It exposes `workload_ids: tuple[str, ...]`, `finding(finding_id: str) -> FindingEntry | None` and `accepts_sku_part_number(part_number: object, guid: str) -> bool`. `catalogue.sku_key(part_number: str, guid: str) -> tuple[str, str]` normalizes lookup keys.
- `model.load_scan(path: Path, catalogue: Catalogue) -> Scan`, `load_scan_text(text: str, file_name: str, catalogue: Catalogue) -> Scan` and `scan_to_json(scan: Scan) -> str` handle the scan. Frozen `Scan` contains `schema_version`, `generated_at` and `source_kind` as strings, `tool: ToolInfo`, `collectors: tuple[Collector, ...]`, `findings: tuple[Finding, ...]`, `licences: Licences | None` and `dropped_count: int`. `ToolInfo(name: str, version: str)` identifies the producer. `Licences(collector: str, source: str, collected_at: str, coverage: Coverage, products: tuple[Product, ...])` holds `Product(sku_part_number: str, sku_guid: str, purchased: int, assigned: int, service_plans: tuple[ServicePlan, ...])` and `ServicePlan(name: str, guid: str)`. Missing plan lists load as an empty tuple. `Finding` carries `id`, `workload`, `value`, `unit`, `provenance`, `collector`, `source`, `collected_at`, `period`, `coverage` and `missing_reason`.
- `rules.load_service_plans(catalogue: Catalogue, path: Path | None = None, *, checksums: MutableMapping[str, str] | None = None) -> tuple[ServicePlan, ...]` returns frozen classification records with `sku_part_number`, `sku_guid`, `name`, `guid`, `signal` and `reference_url` as strings, `workload: str | None`, `checked_on: date` and `note: Mapping[str, str] | None`. The signals are `add_on`, `bundled` and `no_workload`. `classify_product(product: model.Product, plans: tuple[ServicePlan, ...]) -> tuple[ServicePlan | None, ...]` returns matches in observed plan order. `licence_findings(scan: Scan, plans: tuple[ServicePlan, ...], catalogue: Catalogue) -> tuple[Finding, ...]` returns the product count and the derived licence signals. The YAML records `reference_url`, `checked_on`, plan definitions and product rosters grouped by signal.
- `rules.evaluate(findings: Mapping[str, Finding], rule_set: StatusRuleSet, catalogue: Catalogue, *, collectors: Mapping[str, Collector] | None = None, alternatives: Mapping[str, Finding] | None = None) -> tuple[WorkloadStatus, ...]` accepts the selected and alternate observations keyed by finding ID. `Condition(finding: str, op: str, value: FindingValue | None, provenance: str | None = None)` can select an observation by provenance. Frozen `WorkloadStatus(workload: str, status: str, reason_code: str | None, missing: tuple[MissingEvidence, ...], deciding: StatusRule | None, notes: tuple[StatusRule, ...], evidence: tuple[Finding, ...])` exposes `incomplete: bool`. `MissingEvidence(finding_id: str, reason_code: str, collector: str | None)` includes skips and evidence conflicts. `select_evidence(recorded: Finding | None, supplied: Finding) -> Finding` and `evidence_conflicts(measured: Finding, provided: Finding) -> bool` implement precedence for a measured lower bound.
- `rules.load_mapping(profile: str, catalogue: Catalogue, directory: Path | None = None, *, checksums: MutableMapping[str, str] | None = None) -> Mapping` reads the profile. `FunctionMapping.need_finding: str | None` accepts a same-workload boolean or a Windows software count derived from the inputs list. `mapping_need(finding: Finding | None) -> str` returns `yes`, `no` or `unknown`. A positive lower bound can establish need.
- `inputs.load_inputs(path: Path, catalogue: Catalogue) -> Inputs` and `load_inputs_text(text: str, file_name: str, catalogue: Catalogue) -> Inputs`. Frozen `Inputs` holds optional strings `organisation_name`, `currency`, `language`, `target_profile` and `as_of`, booleans `amounts_are_invented` and `answers_are_sample` defaulting to false, `current_costs: CurrentCosts`, `partial_exit: ScenarioInputs`, `full_exit: ScenarioInputs`, `windows_only_software: tuple[WindowsSoftware, ...] | None`, `provided_counts: Mapping[str, int | None]` and `confirmations: Mapping[str, bool | None]`. `answer_source: str` returns `sample.inputs_yaml` or `inputs_yaml`. `provided_findings(inputs: Inputs, catalogue: Catalogue) -> tuple[Finding, ...]` uses that source. `combine(scan: Scan, provided: tuple[Finding, ...]) -> tuple[Scan, tuple[Finding, ...]]` returns selected observations and alternatives, including replaced skipped observations.
- `i18n.Formatter.storage(value: int, *, lower_bound: bool = False) -> str` rounds storage lower bounds down. `report.render_report(scan: Scan, *, lang: str, profile: str = "opendesk", catalogue: Catalogue | None = None, provided: tuple[Finding, ...] = (), inputs: Inputs | None = None) -> str` uses the parsed answer origin. `report.report_file_name(generated_at: str, *, lang: str) -> str` gives `report-<YYYY-MM-DD>-<lang>.html`.
- `befund [--debug] demo [--lang en|de] [--sample town|nonprofit] [--profile opendesk|nextcloud|generic] [--out DIR]` defaults to `en`, `town`, `opendesk` and `./report`. `befund [--debug] report SCAN_JSON [--inputs FILE] [--lang en|de] [--profile opendesk|nextcloud|generic] [--out DIR]` resolves language and profile from the flag, the inputs file, then defaults. Both print the absolute HTML path last. Demo also writes `scan-<YYYY-MM-DD>-<lang>.json` and `inputs-<YYYY-MM-DD>-<lang>.yaml`. `befund.cli:main() -> None` is the entry point. Global `--version` prints the version.

## Deviations and open work

- The reference uses slashes, parentheses and spaces in some EEA SKU identifiers. The catalogue permits 17 verified SKU and GUID pairs as exceptions to the general identifier pattern. Lookup folds case and treats ordinary and non-breaking spaces alike. The grouped service-plan file shares the reference and date across rows and includes the nonprofit's Business Basic product and the retained commercial products.
- The file type and telephony regression fixtures use dedicated simulated inventory sources. Those sources give the review cases meaningful collector and source pairs under A03.
- An initial print check found the expanded E3 plan list split across pages. Grouping plan names by workload and signal fixed the split. The sandbox denied a separate network namespace, so browser verification used Chromium offline emulation with HTTP, HTTPS and WebSocket requests blocked.
