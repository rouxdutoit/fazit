# Plan 01-11 summary

Befund rejects contradictory scan origins, collector reasons, dates, known SKU pairs and declared coverage totals. Licence assignments remain unconfirmed when they contradict the directory count. Confirmed positive counts survive incomplete coverage and smaller supplied totals. Disagreeing interview answers stay visible and cannot decide readiness. Transfer needs use the gaps recorded by readiness. The header shows the scan date beside the date of the inputs. D26, SECURITY.md and both READMEs state that internally consistent fabrications can pass the checks. Both site reports were regenerated.

## Public interfaces

- `catalogue.load_catalogue(path: Path | None = None) -> Catalogue` returns the frozen catalogue. Its fields are `workloads: tuple[WorkloadEntry, ...]`, `findings: tuple[FindingEntry, ...]`, `collector_ids`, `source_codes`, `reason_codes`, `permissions`, `provided_sources` and `licence_sources` as `frozenset[str]`, `file_name: str`, `checksum: str | None` and `sku_exceptions: frozenset[tuple[str, str]]`. It exposes `workload_ids: tuple[str, ...]`, `finding(finding_id: str) -> FindingEntry | None` and `accepts_sku_part_number(part_number: object, guid: str | None) -> bool`. The frozen entries are `WorkloadEntry(id: str, label: str)` and `FindingEntry(id: str, workload: str, type: str, unit: str | None, label: str, provided: str, headline: bool, measured_by: frozenset[tuple[str, str]] = frozenset(), coverage_total_from: str | None = None)`. The optional reference names a distinct count finding in the same catalogue.
- `model.load_scan(path: Path, catalogue: Catalogue) -> Scan`, `load_scan_text(text: str, file_name: str, catalogue: Catalogue) -> Scan` and `scan_to_json(scan: Scan, *, plans: tuple[rules.ServicePlan, ...]) -> str` are the scan I/O. Frozen `Scan(schema_version: str, tool: ToolInfo, generated_at: str, source_kind: str, collectors: tuple[Collector, ...], findings: tuple[Finding, ...], licences: Licences | None, dropped_count: int = 0)` exposes `is_sample: bool`, `finding(finding_id: str) -> Finding | None` and `collector(collector_id: str) -> Collector | None`. The schema supports major version 1. The copy omits the internal dropped count.
- The frozen model records are `ToolInfo(name: str, version: str)`, `Collector(id: str, status: str, reason: str | None, permissions_used: tuple[str, ...])`, `Coverage(kind: str, scanned: int | None = None, failed: int | None = None, total: int | None = None)` and `Finding(id: str, workload: str, value: FindingValue | None, unit: str | None, provenance: str, collector: str | None, source: str | None, collected_at: str | None, period: str | None, coverage: Coverage | None, missing_reason: str | None)`. `FindingValue = int | bool`, and `Finding.is_lower_bound: bool` identifies positive incomplete counts.
- Frozen `model.Licences(collector: str, source: str, collected_at: str, coverage: Coverage, products: tuple[Product, ...])` provides `check_complete_coverage(file_name: str) -> None`. Frozen `Product(sku_part_number: str | None, sku_guid: str | None, purchased: int, assigned: int, service_plans: tuple[model.ServicePlan, ...])` exposes `key: tuple[str, str] | None`. Absent or null SKU fields load as `None`. Frozen `model.ServicePlan(name: str | None, guid: str | None)` holds observed identifiers.
- `rules.load_service_plans(catalogue: Catalogue, path: Path | None = None, *, checksums: MutableMapping[str, str] | None = None) -> tuple[ServicePlan, ...]` returns the frozen classification records. Their fields are `sku_part_number`, `sku_guid`, `name`, `guid`, `signal` and `reference_url` as strings, `workload: str | None`, `checked_on: date` and `note: Mapping[str, str] | None`. `rules.licence_findings(scan: Scan, plans: tuple[ServicePlan, ...], catalogue: Catalogue, *, file_name: str = "scan.json") -> tuple[Finding, ...]` validates known pairs against this roster, then returns product count and assignment signals in catalogue order. `file_name` is used in input errors.
- `rules.evaluate(findings: Mapping[str, Finding], rule_set: StatusRuleSet, catalogue: Catalogue, *, collectors: Mapping[str, Collector] | None = None, alternatives: Mapping[str, Finding] | None = None) -> tuple[WorkloadStatus, ...]`. The frozen result is `WorkloadStatus(workload: str, status: str, reason_code: str | None, missing: tuple[MissingEvidence, ...], deciding: StatusRule | None, notes: tuple[StatusRule, ...], evidence: tuple[Finding, ...])`, with `incomplete: bool`. Frozen `MissingEvidence(finding_id: str, reason_code: str, collector: str | None)` identifies the affected finding. `select_evidence(recorded: Finding | None, supplied: Finding) -> Finding` selects the main observation. `evidence_conflicts(measured: Finding, provided: Finding) -> bool` checks whether a measured positive exceeds a supplied total. `provided_answers_conflict(first: Finding, second: Finding) -> bool` detects differing provided values. `mapping_need(finding: Finding | None) -> str` returns `yes` or `no` from complete evidence and otherwise returns `unknown`. The renderer also applies the finding's readiness gaps.
- `inputs.load_inputs(path: Path, catalogue: Catalogue) -> Inputs`, `load_inputs_text(text: str, file_name: str, catalogue: Catalogue) -> Inputs`, `provided_findings(inputs: Inputs, catalogue: Catalogue) -> tuple[Finding, ...]` and `combine(scan: Scan, provided: tuple[Finding, ...]) -> tuple[Scan, tuple[Finding, ...]]` prepare manual evidence. The last result contains the evaluation scan and alternate observations, including disagreeing answers. Frozen `Inputs` holds `organisation_name`, `currency`, `language`, `target_profile` and `as_of` as optional strings, `amounts_are_invented: bool`, `answers_are_sample: bool`, `current_costs: CurrentCosts`, `partial_exit: ScenarioInputs`, `full_exit: ScenarioInputs`, `windows_only_software: tuple[WindowsSoftware, ...] | None`, `provided_counts: Mapping[str, int | None]` and `confirmations: Mapping[str, bool | None]`. Its `answer_source: str` is `inputs_yaml` or `sample.inputs_yaml`.
- `report.render_report(scan: Scan, *, lang: str, profile: str = "opendesk", catalogue: Catalogue | None = None, inputs: Inputs | None = None, scan_file_name: str = "scan.json") -> str` returns HTML. `scan_file_name` is for diagnostics. `render_demo(scan: Scan, *, lang: str, profile: str, catalogue: Catalogue, inputs: Inputs) -> tuple[str, str]` returns HTML and the scan copy. `report_file_name(generated_at: str, *, lang: str) -> str` returns `report-<YYYY-MM-DD>-<lang>.html`. Header dates use `data-input-role="scan"` and `data-input-role="inputs"`. `output.write_inside(out_dir: Path, file_name: str, text: str) -> Path` and `write_files(out_dir: Path, outputs: Mapping[str, str]) -> tuple[Path, ...]` return the resolved output paths.
- The Typer app is `befund.cli.app` and the entry point is `befund.cli:main() -> None`. `befund [--debug] demo [--lang en|de] [--sample town|nonprofit] [--profile opendesk|nextcloud|generic] [--out DIR]` defaults to `en`, `town`, `opendesk` and `./report`. `befund [--debug] report SCAN_JSON [--inputs FILE] [--lang en|de] [--profile opendesk|nextcloud|generic] [--out DIR]` resolves language and profile from flags, inputs and defaults. Both support `--help` and print the absolute HTML path last. Demo also writes `scan-<YYYY-MM-DD>-<lang>.json` and `inputs-<YYYY-MM-DD>-<lang>.yaml`. Global `--version` prints the installed version. Input errors print one localized sentence and exit 2 unless `--debug` exposes the exception.

## Deviations and open work

- The header uses the logical names `scan.json` and `inputs.yaml` to preserve privacy for caller-selected filenames. It shows the dates without trying to identify whether files belong to the same organisation.
- An anonymous zero-seat replacement is internally consistent when other products still account for the licensed directory. It contributes no assignment signal as specified, so that gate variant can still pass under D26. A known identifier with a missing or mismatched counterpart fails the pair check. Known zero-seat products still need the full published roster under the earlier 01-10 safeguard.
- Date-only values compare calendar dates. Two explicit offsets compare instants, and a timestamp with an omitted offset uses wall time. The collection-date check also applies to the licence block because its date becomes evidence in the report.
- Both `inputs_yaml` and `sample.inputs_yaml` are reserved for inputs loaded from the YAML file. The resulting scan fixtures use supported sources and keep their privacy assertions.
- Phase 2 backlog. Unknown-coverage zeros still print as exact counts alongside the coverage warning.
