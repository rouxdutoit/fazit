# Output writes on macOS

macOS CI ran CPython 3.12.10, whose `os.supports_dir_fd` omits `os.lstat`. That sent Fazit to its pathname fallback. In the `[False]` case, staging succeeds and the test expects the new report in the moved directory. The same assertion failed on Linux with 3.12.10 before the fix. Ubuntu CI ran 3.12.16, whose capability table lists `os.lstat`. [CI run](https://github.com/rouxdutoit/fazit/actions/runs/45254197259) · [3.12.10 capability table](https://github.com/python/cpython/blob/v3.12.10/Lib/os.py#L108-L125) · [3.12.16 capability table](https://github.com/python/cpython/blob/v3.12.16/Lib/os.py#L99-L117)

Fazit now detects and uses `os.stat` with `dir_fd` and `follow_symlinks=False` for anchored destination checks. CPython uses `fstatat` with `AT_SYMLINK_NOFOLLOW` for that call and `renameat` for both `os.rename` and `os.replace` with directory descriptors. Windows uses the resolved pathname and `os.lstat`. The regression checks that staging uses the original directory's descriptor in both cases. [Python documentation](https://docs.python.org/3.12/library/os.html#os.lstat) · [CPython stat implementation](https://github.com/python/cpython/blob/v3.12.10/Modules/posixmodule.c#L2660-L2706) · [CPython rename implementation](https://github.com/python/cpython/blob/v3.12.10/Modules/posixmodule.c#L5525-L5644)
